# 离线证据检查与方法效果评测

首版有两种验收范围。可执行检查验证随仓库携带的证据摘要、改进链和案例结论。方法效果评测比较 agent 在相同任务与预算下的实际表现，首版状态为 `not_run`。

## 可执行证据检查

从仓库根目录运行 `python3 scripts/check_repository.py`。`evidence.json` 保存小型汇总字段和来源哈希，`checks.json` 指定真实结果断言。原始数据、序列和大模型继续位于项目归档。加 `--project-root` 后检查来源文件哈希及摘录字段，从其他目录也可以调用。

历史失败实验可以是正确的回归预期。例如错峰 wave02 的保护停止要保持失败标识，案例断言通过只表示证据支持这个状态。检查不调用 GPU、Java、评分或远程服务，也不重新执行已归档原实验。

[repository-check.json](repository-check.json) 是首版证据检查记录。[checker-regression.json](checker-regression.json) 记录隔离副本、证据篡改、关系成环、错误断言与来源变化的回归结果。这两项的范围都是本地证据检查。

## 开发任务

[tasks.json](tasks.json) 给出问题、输入证据及输出要求，[rubric.json](rubric.json) 给评审使用。任务覆盖 kernel 收益与误差、排队归因、保护缺陷、并跑状态、恢复判断和指标分母。它们来自已经写入 Skill 的案例，作为开发与回归任务。

需要比较方法效果时，固定任务包、输入哈希、模型和运行时、工具、wall/time 或 token 预算，以及可以发生的副作用。基线只得到相同任务的原始材料，候选条件额外获得指定版本的 Skill 和辅助工具。分别保存两边实际输出、工具调用、用时、资源消耗、人工纠正和失败原因。由评审按同一 rubric 给分，方法收益应与正确性、执行成本和稳定性一同报告。

## 迁移验证

后续从未参与编写本 Skill 的任务冻结独立测试包。预期答案和判定字段由评审保管，评测输入只包含完成任务所需材料。两种条件使用相同授权与预算，在独立输出目录运行。先做只读诊断、覆盖验收和恢复规划，需要真实资源实验时按该次任务的授权推进。

出现新失败后记录新节点、修改相关产物并重放受影响开发任务。先冻结独立测试包再评估新版本的迁移表现。首版尚无这种盲测结果，`registry.json` 如实记录状态。
