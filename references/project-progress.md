# 项目进度与中断接续

长时间 CPU/GPU 任务可能使当前终端、会话或容器中断。实验开始前，把继续工作所需的状态落到持久项目目录，让重新启动的 Codex 或其他 harness 能读取并接续。

## 按工作方向维护进度

在被评测或被优化的项目中维护 `agent-progress/`。按长期方向组织，例如 GPU 性能、CPU 诊断、标准评测。每个方向用一份主要记录，更新已有小节，README 提供简短导航。记录当前目标、用户决定、已验证结论、适用边界、未解决项和复现入口。

原始日志、命令、配置和结果随实验保存在 `experiments/` 等运行目录。进度文档链接到这些产物，避免把全部日志复制进长期总结。新结果推翻旧结论时，更新采用状态与原因，并保留反例的证据入口。

## 启动前写当前交接

可能使环境中断的实验，先在项目 `agent-progress/.chat/` 中写当前任务交接。至少记录目标与用户决定、输入和配置身份、启动命令、运行目录、进程识别方式、日志和结果位置、停止条件，以及重连后先查什么。

简短交接可以按以下顺序填写。

```text
目标与本次运行范围
输入、配置和执行入口
运行目录、进程身份、日志与产物
已完成检查与当前阶段
保护或停止条件
恢复后优先检查项
```

运行中更新同一份交接的启动确认、检查点、异常和变更。完成或失败后，把可复用结论写回该方向的进度，将交接随实验归档，让 `.chat/` 只保留当前任务。

## 恢复 harness 后接续

先按 [账户恢复](recovery.md#账户备份与-harness-恢复) 恢复账户访问，再读取项目方向导航和当前交接。核对原任务是否仍活跃、最后日志和心跳、保护事件、输出完整性及机器或容器身份。把新观测写入交接后，再决定等待、停止、续跑或创建新 attempt。
