# 故障恢复、运维线索与混合负载

## 账户备份与 harness 恢复

可能卡死、重启或丢失容器的实验，提前让用户准备 Codex 或当前 harness 的账户恢复方式。依据实际认证方式，把需要的账户密钥、API key 或 harness 支持的登录备份复制到不会随实验环境丢失、且只有用户能访问的私密位置，例如个人设备的私有存储或受控的持久目录。

由用户确认私密备份可访问、文件权限受限，并记录从该位置恢复账户的方法。会失效或被撤销的登录凭据保留重新授权入口。按 harness 实际支持的认证流程恢复，先确认账户访问成功，再读取项目进度继续任务。备份路径和真实凭据由用户私有渠道维护。

本机的 `/mnt/ai4s/zhangjianyang/recover/` 提供了账户备份与恢复的使用场景。RSI 提炼的是提前保全账户访问的方法，具体文件形式和重新授权流程按用户当前 harness 确定。

任务接续所需的目标、决定、运行命令、日志和验收边界写入使用方项目的持久记录，维护方式见 [项目进度与中断接续](project-progress.md)。

## 从运维线索缩小范围

恢复连接后，先核对原进程身份、最后心跳、退出和 guard 状态，再判断续跑。boot ID 与容器启动时间帮助识别宿主或容器变化。向运维提供异常时间窗和节点、容器标识，获取最小可定位的报错或事件原文。

探针问题核对 liveness/readiness 类型、每次超时及后续动作。内核告警核对 watchdog、CPU 和调用路径。资源问题核对 OOM、内存事件与 CPU/I/O 压力。把平台事件和应用 trace 对时，保留进程创建、退出、等待点和执行阶段，逐步缩小到组件或具体调用。候选锁地址与持锁方需要对应的直接证据。

## 保护要能追溯历史事件

对每个 probe ID 固定 launch 和 exit 起点，检查进行中阶段年龄与已完成阶段真实耗时。逐条检查相邻 heartbeat 间隔和末条年龄，保留所有越界。用失败记录验证检出，用成功记录检查误报，结束后独立重放原始事件。

自动保护触发后保全本轮目录。按约定停止受影响任务，复核主机恢复、剩余任务健康和结果状态，再决定是否继续其他计算。部分输出的可用性依赖覆盖与来源验收。

## CPU/GPU 同机错峰

先取得独跑资源与耗时基线。GPU 工作也会占用 CPU、内存和存储。插入点结合所有目标 worker 的递增批次进度、实际设备活动，以及连续主机健康窗口决定。每个波次都重新检查并持续监测，按两项都完成后的总墙钟及正确性评估调度收益。

案例中约第 8–10 分钟开始检查、90 秒 readiness、30 秒基线和 5/8 秒保护阈值均是 D 集群的选择。错峰第一波通过、第二波仍超时，适用范围见 [保护控制器案例](../cases/protection-controller/README.md)。
